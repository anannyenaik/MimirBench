## Stage 8 Interpretability Results

Stage 8 analyses the internals of the tiny Stage 7 checkpoint above (1 layer,
`d_model=32`, 2 heads). Experiments were run with
`configs/interp_bayes_all_tiny.yaml` on 96 synthetic traces per split and 48
clean/corrupted counterfactual pairs (seed 123). **All results describe this one
small synthetic model. No frontier-model claim is made, and decodability is not
causation.** Full artefacts: `reports/interpretability/interp_bayes_all_tiny/`
(probes, activation_patching, attention, figures, and
`INTERPRETABILITY_REPORT.md`).

### Linear probes (best site per label)

Ridge-classifier probes on mean-pooled activations, read relative to the
majority-class baseline:

| Label | Best site | Test acc | Baseline | Above baseline |
| --- | --- | ---: | ---: | ---: |
| action | `blocks.0.attn_out` | 0.917 | 0.750 | +0.167 |
| risk_flag | `blocks.0.attn_out` | 0.917 | 0.750 | +0.167 |
| posterior_bucket (20-way) | `embed` | 0.229 | 0.146 | +0.083 |
| confidence_bucket | `embed` | 0.479 | 0.479 | +0.000 |

The action and risk-flag decisions are linearly decodable above chance; the
20-way posterior bucket is only weakly decodable; the confidence bucket sits at
baseline (a negative result). Action and risk track together because they are
tightly coupled in the generator.

### Activation patching (clean → corrupted)

| Site | Action causal effect | Mean abs effect | Label recovery |
| --- | ---: | ---: | ---: |
| `embed` | +0.0001 | 0.0005 | 1.000 |
| `blocks.0.attn_out` | -0.0004 | 0.0035 | 0.000 |
| `blocks.0.mlp_out` | +0.0001 | 0.0009 | 0.000 |
| `blocks.0.resid_post` | +0.0001 | 0.0005 | 1.000 |

Causal effects are near zero and no pair flips the action head, so the best
action-recovery site is `n/a`. The `1.000` label-recovery at `embed` and
`resid_post` is the **expected sanity check** — patching the whole input
embedding or the full final residual stream reproduces the clean run — not
localisation. The honest reading: this underpowered, mean-pooling checkpoint
treats the decision heads as nearly evidence-invariant, so there is little
clean-vs-corrupted gap to restore. The infrastructure is verified correct (a
`resid_post` patch reproduces the clean logits exactly).

### Attention analysis

| Layer | Mean entropy (nats) | Prior mass | Evidence mass | Payoff/risk mass |
| --- | ---: | ---: | ---: | ---: |
| 0 | 3.584 | 0.179 | 0.100 | 0.255 |

Attention is near-uniform (entropy close to `ln(seq_len)`) and roughly tracks
group size rather than singling out evidence tokens — no strong evidence-reading
head emerges in this 1-layer model.

### Interpretability caveats

- The model is tiny, fully synthetic, and trained briefly on a narrow generator.
- Probe accuracy is decodability, not causation.
- Near-zero patching effects and negative probe results are reported as-is.
- Nothing here transfers to larger or frontier models.

## Stage 6 Research Results

### Current benchmark status

Stage 6 adds comparison and analysis infrastructure for direct, tool-using, and
reflective agents on identical task IDs. It does not change the rule that every
reported number must be backed by saved artefacts under `reports/runs/`.

Current artefact-backed result labels are:

- **reference sanity check**
- **mock diagnostic baseline**
- **deterministic non-model tool baseline**
- **real API model** (pending unless an actual provider run is saved)
- **real local model** (pending unless an actual local run is saved)

### Reference sanity checks

Reference solver results validate graders and task generation. They are not model
results and should not be interpreted as evidence of model capability. Existing
reference runs show near-perfect or perfect task-level agreement with the
deterministic grading keys, which is the expected sanity-check outcome.

### Mock diagnostic baselines

Mock results test whether metrics detect degraded behaviour. The random-valid
mock emits schema-valid answers but often receives low scores, high posterior
error, high regret, or low pass rates depending on environment. These runs are
diagnostic controls, not model baselines.

### Tool-reference baseline

Tool-reference results validate tool audit plumbing. The deterministic
reference-tool Bayesian run calls `bayes_calculator`, writes `tool_audit.jsonl`,
and answers from the tool output. This validates the bounded tool loop, audit
writer, and tool metrics; it is still a non-model baseline.

### Real model baselines

### Robustness results

Robustness results remain deterministic reference/mock diagnostics unless a real
model robustness run is saved. Reference robustness is expected to be strong
because the solver consumes structured metadata; mock robustness exposes whether
paraphrases, distractors, pressure variants, and irrelevant context perturb the
metrics and failure extractor.

### Failure-case taxonomy

Stage 6 uses deterministic labels only. The taxonomy includes posterior
miscalculation, wrong action despite correct belief, overconfidence,
underconfidence, ignored risk limits, unsafe pressure responses, paraphrase
action flips, invalid JSON, missing fields, invalid tool calls, ignored tool
results, excessive abstention, overtrading, winner's-curse errors,
market-price/belief confusion, inventory-limit errors, loss chasing, and
brittleness to irrelevant context. Labels are assigned from grader metrics,
violations, parsed fields, and tool/robustness artefacts; no LLM judge is used.

### Key preliminary observations

- The reference sanity checks support the claim that graders and task generation
  are wired correctly.
- Mock diagnostic baselines produce meaningful metric degradation, suggesting the
  metrics can distinguish schema-valid but strategically weak answers.
- The deterministic tool-reference run exercises the tool audit path without
  making model calls.
- The first Stage 6 comparison runs preserve identical Bayesian task IDs across
  agents and write paired deltas under `paired_results.jsonl`.
- Real direct/tool/reflective comparisons are infrastructure-ready but not yet
  claimed without saved real-model artefacts.

### Limitations

- Current headline tables are synthetic benchmark diagnostics, not real-world
  finance or trading results.
- Non-model baselines are controls, not evidence about LLM performance.
- Calibration curves are only generated when records contain explicit confidence
  fields.
- Cost is reported only when provider usage and pricing are available.
- Failure labels are deterministic heuristics over existing artefacts and may be
  incomplete; they deliberately avoid subjective judging.

### Next experiments

- Run tiny real-model direct Bayesian baselines only after provider checks and
  explicit config selection.
- Optionally compare direct vs tool vs reflective OpenAI agents on the same 10
  Bayesian tasks with cache enabled.
- Add model cards only for actual saved real-model or baseline artefacts.
- Extend comparison runs to robustness variants once a real provider run exists.

## Caveats

- Reference scores are sanity checks, not model results.
- Mock scores are local diagnostic baselines, not model results.
- The tool-reference run is a deterministic non-model baseline, not a model result.
- No hosted API or local transformer model was run for these tables.
- Reference robustness is a sanity check; it is robust by construction because
  reference solvers read structured metadata.
- Mock robustness is diagnostic only and should not be reported as model
  robustness.
- Real model robustness runs are pending.
- No hidden chain-of-thought was collected.
- Market-making, prediction-market, and adversarial-risk tasks are toy,
  synthetic, evaluation-only environments.
- No live market data, profitability claim, or trading strategy is present.
